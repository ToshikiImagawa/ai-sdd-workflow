| adr エントリ                          | 現行の決定             | spec の記述                | ステータス                              |
|:----------------------------------|:------------------|:------------------------|:-----------------------------------|
| `## {YYYY-MM-DD} {決定タイトル}`        | {決定内容}           | {対応する spec の記述}        | 🟢 整合 / 🔴 spec と矛盾               |
| `## {YYYY-MM-DD} {決定タイトル}`        | 後続エントリにより覆された    | {それに依拠したままの spec の記述}  | ⚪ 履歴 / 🔴 spec が覆された決定に依拠         |
| {spec を駆動する決定（例: 永続化方式の選択）}      | adr に未記録         | {根拠が未記録の spec の記述}      | 🟡 未記録                             |

**基準**:
- 🟢 **整合**: 現行の決定（同一トピックの最新・未覆エントリ）が spec の記述と一致している
- 🔴 **spec と矛盾**: 現行の決定と spec の記述が食い違っている
- ⚪ **履歴**: 後続エントリの `Supersedes` に指名されたエントリ。履歴として読み、現行の決定として扱わない
- 🟡 **未記録**: spec が述べる振る舞いの背後にある設計判断を、どのエントリも記録していない

対象機能の決定ログが解決できなかった場合は**該当なし**と記載する。「整合」と書いてはならない。決定ログが
無いことは、決定が未記録の機能では通常状態である。
