### ファイル一覧

| ファイル    | 最終更新日      | ステータス       |
|:--------|:-----------|:------------|

### 統合すべき内容（→ `adr/{feature}.md` へ追記）

決定1件につき `## YYYY-MM-DD {タイトル}` エントリを1件、ファイル末尾へ追記する（append-only）。

- [ ] **{決定1}**: {概要（Decision / Rationale / Rejected alternatives）}
    - 統合先: `${SDD_ADR_PATH}/{name}.md`
    - エントリ見出し: `## {YYYY-MM-DD} {決定タイトル}`
- [ ] **{決定2}**: {概要}
    - 統合先: ...

### 追記結果の検証（削除の前提条件）

追記後にファイルをディスクから再読込して確認する。すべて「確認済み」でなければ削除しない。

| 追記したエントリ           | 追記先                            | Decision / Rationale / Rejected alternatives | 既存エントリの保持 | 結果             |
|:-------------------|:-------------------------------|:---------------------------------------------|:----------|:---------------|
| `## {日付} {タイトル}` | `${SDD_ADR_PATH}/{feature}.md` | {確認済み / 欠落: {項目}}                            | {保持 / 変化} | {確認済み / **失敗**} |

- front matter の各フィールド: {確認済み / 欠落: {フィールド}}
- 手順7で編集したその他のドキュメント: {確認済み / 欠落: {ファイル}: {フィールド}}
- **削除の判断**: {実行する / **中止** — task/ を残し、上記の欠落を報告}

### 削除可能な内容

- `{ファイル1}`: 一時的な調査ログ
- `{ファイル2}`: 作業進捗メモ
- `{ファイル3}`: 完了済みタスクリスト

### ADR に残さない知見の退避先

`adr/` は決定の記録であり、ノウハウ置き場ではない。削除する内容のうち再利用価値のある知見は退避先を示す。

| 知見             | 退避先候補                                 |
|:---------------|:--------------------------------------|
| {実装のコツ・デバッグメモ} | {コードコメント / 振る舞いを固定するテスト / `*_spec.md`} |

### チケットへのダンプ内容

- 対象チケット: `{ticket-number}`
- 投稿する要約: {ADRへ追記した決定・Spec更新提案の結果・削除したファイルの要約}

### 実行するアクション

1. {決定} を `${SDD_ADR_PATH}/{feature}.md` に追記（決定ごとに1エントリ）
2. 追記結果をディスクから再読込して検証（上記「追記結果の検証」）
3. 検証が通った場合のみ `task/{対象}/` を削除（git 追跡下なら `git rm`、未追跡なら `rm`。いずれも都度確認を求められる）
4. チケット `{ticket-number}` へ要約をコメント投稿

### 確認事項

- [ ] 統合すべき決定・却下した代替案を見落としていないか
- [ ] 追記したエントリがファイル上に実在し、既存エントリが書き換わっていないか
- [ ] 削除対象に重要な情報が含まれていないか
- [ ] Spec更新トリガーの判定に漏れがないか
- [ ] チケットへのダンプ内容が要約として十分か
- [ ] v4.x の `specification/*_design.md` を削除対象に含めていないか（対象外）
