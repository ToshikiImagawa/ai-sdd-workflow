### 次のステップ

1. PRDの内容を確認し、必要に応じて調整
2. `/generate-spec` で抽象仕様書と技術設計書ドラフトを作成する（Specify フェーズのPRDに続く次フェーズ）。
   設計書ドラフトは `${SDD_TASK_PATH}/{チケット番号}/design-draft.md` に書き込まれるため、チケット番号を渡す:

   ```bash
   /generate-spec --ticket {チケット番号} {要求内容}
   ```

   `--ticket={チケット番号}` も受理される。対話モードではフラグを省略するとチケット番号を質問されるが、
   `--ci` ではフラグが必須で、無いと実行が中止される
3. PRDの要求IDを仕様書で参照

### 検証コマンド

**この時点で実行できるもの** — PRDのみが存在し、`${SDD_SPECIFICATION_PATH}/` はまだ作成されていない:

```bash
# 明確度スキャン。仕様書が存在するまではPRDのみを対象に実行される
/clarify {機能名}
```

`/clarify` は `requirement/**` に書き込まないため、回答をPRDへ反映することはできない。回答は上の
`/generate-spec` の入力に含めるか、PRDを手で編集して取り込む。

**`/generate-spec` が仕様書を作成した後に実行できるもの** — `/check-spec` は
`${SDD_SPECIFICATION_PATH}/` を読むため、そのディレクトリが無い状態ではエラー終了する。
PRD生成直後の次ステップとして案内してはならない:

```bash
# 総合レビュー（ドキュメント間整合性: PRD ↔ 仕様書 ↔ adr と品質）
/check-spec {機能名} --full
```
