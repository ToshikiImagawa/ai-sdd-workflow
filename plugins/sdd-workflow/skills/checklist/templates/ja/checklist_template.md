## チェックリストサマリー

| カテゴリ        | 総項目数 | P1 | P2 | P3 |
|:------------|:-----|:---|:---|:---|
| 要求レビュー      | -    | -  | -  | -  |
| 仕様レビュー      | -    | -  | -  | -  |
| 設計レビュー      | -    | -  | -  | -  |
| 実装レビュー      | -    | -  | -  | -  |
| テストレビュー     | -    | -  | -  | -  |

| セキュリティレビュー  | -    | -  | -  | -  |
| パフォーマンスレビュー | -    | -  | -  | -  |
| デプロイレビュー    | -    | -  | -  | -  |

**優先度レベル** — この定義をSKILL.md本文と実際に比較し、一致していたか、または齟齬を見つけて
解消したかをここに記録すること（この一文をそのまま比較の記録として流用しない）:

- **P1 - High**: マージ前に必須（PR作成前に確認）
- **P2 - Medium**: マージ前に完了すべき（PRレビュー中に確認）
- **P3 - Low**: あると望ましい（機会があれば確認）

**カテゴリとID番号の対応**（`CHK-{カテゴリ番号}{連番}` 形式。`run-checklist` の検証ロジックもこの対応関係に依存する）:

`CHK-1xx`=要求, `CHK-2xx`=仕様, `CHK-3xx`=設計, `CHK-4xx`=実装, `CHK-5xx`=テスト,
`CHK-6xx`=ドキュメント, `CHK-7xx`=セキュリティ, `CHK-8xx`=パフォーマンス, `CHK-9xx`=デプロイ

**根拠**（項目ごとに必須）: どの文書のどの記述から抽出したか（例: `PRD FR-003`、`design §6 アーキテクチャ`）。
文書からの引用ではなく実装コンポーネントの存在から導いた場合は `synthesized from: {コンポーネント名}` と明記する。
